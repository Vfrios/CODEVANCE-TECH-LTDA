# Controle de versão — CodeVance Tech

## Versão 1.0

**Data de registro:** 01/10/2026  
**Status:** Base inicial implementada  
**Tipo:** Primeira versão funcional do site institucional

## Resumo

A versão 1.0 entrega a base pública do CodeVance Tech como uma Single Page Application (SPA) responsiva. O foco desta versão foi estruturar a identidade visual, apresentar os serviços da empresa, criar os canais de contato e preparar a aplicação para a evolução futura do backend e do Painel ADM.

## O que foi implementado

### Site institucional

- Página inicial em `src/pages/Home.jsx`.
- Navegação por seções: início, soluções, como funciona, valores, sobre e contato.
- Apresentação de problemas comuns das empresas e respectivas soluções.
- Seções de serviços para criação de sites e desenvolvimento de softwares sob medida.
- Processo comercial em cinco etapas, do contato inicial à entrega e suporte.
- Planos e valores de referência para sites e softwares.
- Indicadores institucionais com contadores animados.
- Seção sobre a empresa e seus pilares: transparência, proximidade e resultado.
- Formulário de contato com validação de nome, e-mail e mensagem.
- Links de contato para WhatsApp, e-mail, Instagram e localização.
- Rodapé com navegação e informações institucionais.

### Interface e experiência

- Layout responsivo para desktop e dispositivos móveis.
- Tema visual baseado em Mantine 8, com identidade escura e cor principal verde.
- Migração dos componentes de interface para Mantine.
- Ícones utilizando `@tabler/icons-react`.
- Animações de entrada, hover, parallax, scroll spy e contadores.
- Suporte à preferência de redução de movimento do usuário.
- Menu mobile e navegação fixa com comportamento adaptativo durante a rolagem.
- Botão flutuante de WhatsApp exibido após a rolagem da página.
- Configuração centralizada de identidade, contatos, planos e preços em `src/config/site.js`.

### Estrutura da aplicação

- React 18 com JSX e Vite 8.
- React Router DOM para roteamento.
- TanStack React Query configurado para estado de servidor.
- Providers centralizados em `src/app/providers.jsx`.
- Tema Mantine centralizado em `src/theme.js`.
- Alias `@/` configurado para imports internos a partir de `src/`.
- Cliente HTTP genérico preparado em `src/services/api.js`.
- Estrutura modular organizada por features em `src/features/`.

### Autenticação e rotas preparadas

- Telas de login, cadastro, recuperação e redefinição de senha.
- Tela de consentimento OAuth preparada para integração futura.
- `AuthProvider`, `ProtectedRoute` e validação de `returnTo` implementados.
- Proteção contra redirecionamento para origens externas em `safeReturnTo`.
- Fluxo de autenticação mantido em um único adaptador, `src/services/auth-mock.js`, para facilitar a troca por um backend real.

### Backend inicial

- Servidor Node.js iniciado junto com o frontend pelo comando `pnpm dev`.
- Endpoint de verificação disponível em `GET /api/health`.
- Estrutura de pastas preparada para rotas, controllers, schemas, módulos, serviços, repositórios, integrações, migrations, seeds, jobs e testes.
- Proxy do Vite preparado para chamadas `/api/*`.

### Build e publicação

- Scripts de desenvolvimento, build, preview, lint e typecheck configurados no `package.json`.
- Workflow `.github/workflows/deploy.yml` configurado para:
	1. instalar Node.js 22 e pnpm;
	2. instalar dependências com lockfile;
	3. executar o build de produção;
	4. publicar o conteúdo de `dist/` na branch `deploy`.
- Estratégia de hospedagem preparada para a Hostinger sincronizar a branch `deploy` com `public_html`.
- Fallback do React Router preparado para hospedagem Apache por meio de `.htaccess`.

## Limites conhecidos da versão 1.0

Os itens abaixo possuem estrutura ou telas preparadas, mas ainda não representam funcionalidades completas em produção:

- A autenticação real ainda não está conectada. `src/services/auth-mock.js` rejeita login, cadastro, OAuth, recuperação de senha e demais operações com erro de configuração.
- O servidor atual é um placeholder Node.js e implementa somente `GET /api/health`.
- O formulário de contato valida e exibe confirmação local, mas ainda não envia dados para e-mail, API ou serviço externo.
- O Painel ADM, catálogo, orçamentos, chatbot, cadastros, configurações e permissões estão documentados ou com estrutura de pastas preparada, mas ainda dependem da implementação do backend e das telas correspondentes.
- Os dados institucionais, contatos e alguns preços ainda contêm valores de configuração ou placeholders que devem ser revisados antes da publicação definitiva.
- Não há banco de dados ou persistência real conectados nesta versão.

## Próximas implementações sugeridas

1. Substituir `src/services/auth-mock.js` por autenticação real com sessão segura, hash de senha e controle de permissões.
2. Implementar o backend da API com validação, tratamento de erros e persistência.
3. Criar banco de dados, migrations e seeds.
4. Conectar o formulário de contato a um endpoint ou serviço de envio.
5. Implementar o Painel ADM por módulos, começando por autenticação, dashboard, cadastros e orçamentos.
6. Revisar os dados reais de contato, logo, cidade, Instagram e preços em `src/config/site.js`.
7. Adicionar testes automatizados para os fluxos públicos e da API.
8. Confirmar a configuração da Hostinger e validar o deploy da branch `deploy` em produção.

## Validação registrada

- Build de produção: executado com `pnpm build` conforme a documentação de migração para Mantine.
- Lint: disponível pelo comando `pnpm lint`.
- Typecheck: disponível pelo comando `pnpm typecheck`.
- Endpoint local de saúde: `GET http://localhost:3001/api/health`.
